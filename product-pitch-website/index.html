Safety

Checks its own work at every step.

Version selection

  • Lowest safe version within the same major first
  • Cross-major only as a last resort
  • Registry-confirmed before selection (npm & Gradle)*
  • Xray re-scanned for new CVEs
  • No safe version found → manual review, not a guess

Build isolation

  • Build fails → steps down to an intermediate safe version before reverting entirely
  • No single culprit → accumulates reverts until build passes
  • Rescue pass removes unnecessary reverts
  • Result: minimal revert set, maximum fixes kept

Real failures vs. pre-existing ones

  • A failing test after the update isn't automatically blamed on it
  • Gradle: rebuilds against the original file — same test already failing there? Kept, not rolled back
  • Node: reruns the suite against the pre-remediation package.json (git HEAD) — same failing suite there? Same treatment
  • Only genuinely new failures trigger isolation/rollback

Two-phase execution

  • Phase 1: fast pass across every repo — no isolation trials, so one slow build never blocks the batch
  • Phase 2: opt-in deep pass — replays the cached plan with isolation enabled for repos still needing review
  • Phase 2 replay re-clones automatically if the original checkout is gone

Ecosystems

Each one handled natively.

npm

package.json · package-lock.json · overrides

The problem

  • Multiple versions of the same package can coexist in the lockfile
  • Registry blocks surface as 403 at install time, post-merge

What it does

  • Reads the full lockfile including all transitives
  • Probes each candidate for registry block status
  • Writes a direct pin or override to reach the vulnerable copy
  • Runs npm install; rolls back on failure

Gradle

build.gradle · resolution strategy · Artifactory Maven

The problem

  • Each configuration resolves independently — clean compile ≠ clean runtime
  • Most scanners only check one configuration

What it does

  • Resolves all four: runtimeClasspath, compileClasspath, testRuntimeClasspath, testCompileClasspath
  • Queries Artifactory Maven metadata; confirms accessibility before selecting
  • Runs ./gradlew build; rolls back on failure

Python

requirements.txt · pyproject.toml · Poetry · pip

The problem

  • Three formats, each with different pinning syntax
  • Private pip indexes can block versions silently

What it does

  • Detects and parses all three formats
  • Applies same semver selection logic as npm and Gradle
  • Runs pip install; rolls back on failure
