The problem

Most dependency bots stop before the risky part.

They open a version bump and leave developers to discover blocked artifacts, transitive dependency conflicts, missing Maven mappings, and compile failures. That turns “automation” into manual cleanup.

!

CVE tasks are ambiguous

Security work items often reference CVEs, products, or prose instead of exact package coordinates.

403

Repositories block versions

JFrog or Artifactory can reject a version even when public metadata says it exists.

⌁

Transitives break builds

Gradle can resolve blocked artifacts through BOMs, strict declarations, or compileClasspath after an update looks safe.

The solution

A pipeline that behaves like a senior engineer reviewing the change.

Dependency Rescue combines deterministic CVE resolution, constrained AI assistance, Xray vulnerability checks, artifact block checks, safe forward/backward version search, and final build validation.

  • Claude resolver is constrained to known project dependencies.
  • Xray eliminates versions with CVEs before Artifactory accessibility checks.
  • Node checks all package dependencies, not only ADO-mentioned packages.
  • Gradle checks resolved dependencies across key configurations and final build failures.
  • If a candidate breaks the build, the pipeline isolates it, rolls it back, or marks it manual.

Workflow

From work item to validated build.

The pipeline turns security tasks into dependency changes, but the build is the final authority.

1

Import ADO story and child CVE tasks.

2

Resolve packages deterministically with OSV/NVD, Maven product matching, and cached Claude fallback.

3

Generate available version candidates for Node or Gradle.

4

Filter candidates through JFrog Xray CVE search.

5

Run block/accessibility checks against package registries and Artifactory.

6

Try forward versions first, then safe same-major backward fallbacks when needed.

7

Write dependency updates, direct rewrites, lockfile changes, and Gradle force overrides.

8

Run the real project build and auto-remediate blocked final-build artifacts.

Why teams trust it

Safety rails are built into every stage.

Known-package AI

Claude can help interpret vague CVE task text, but results are validated against the project dependency universe before use.

Vulnerability-first filtering

Xray search removes vulnerable candidate versions before the pipeline even attempts a block check.

Build-backed confidence

The update is not considered successful until npm or Gradle validation passes in the target project.

Automatic recovery

When a build fails, the pipeline identifies the package, tries safe alternatives, rolls back isolated offenders, or marks manual updates.

Gradle transitive coverage

Blocked artifacts discovered during compileClasspath or final build are treated as block-check events, not ignored as generic failures.

Actionable reporting

CSV and spreadsheet outputs show auto fixes, external blockers, skipped packages, and manual-update requirements.
